# Live runtime client

Current game builds use `Screamer Rally.app` and include Classic and Upgraded modes in one app. Internal support folders retain their legacy Metal names; older standalone wrappers and their saves remain separate.

The renderer accepts `--live /path/to/state.json --input /path/to/input.json`. Without `--live`, captured-scene/replay behavior remains available. The lifecycle supervisor owns the DOSBox process, audio, bridge worker, session folder and shutdown; the renderer does not launch or advance the game.

For a normal GUI launch, an enabled bundled `Resources/LiveConfig.json` starts `Resources/Python/bin/python3.14 Resources/Live/Session.py` with the resource path, a fresh UUID session directory, the shared GameData directory and the renderer's parent PID. The app owns the NSTask and redirects its output to `session.log`. Python uses its bundled home, disables user-site imports and bytecode writes, and exits through the session supervisor. Closing the app releases keys and terminates that supervisor; the supervisor's parent-PID watcher is an additional cleanup path. Startup, disconnect and runtime-failure states have a visible status overlay. Explicit `--live`, `--offscreen` and `--check-math` skip automatic session startup.

Live state follows `screamer-live/v1`. A background reader observes atomically replaced files, accepts monotonically increasing sequences within one session epoch, and keeps a bounded queue of immutable snapshots. Race camera/car poses are interpolated one configured physics period behind observation time; the display loop targets 60 Hz independently. Missing/replaced car IDs or model mismatches are omitted; large jumps and sample gaps snap rather than inventing intermediate motion. A stale feed releases input and uses the original-frame fallback.

Repeated pose timestamps update framebuffer/status metadata without adding duplicate interpolation samples. Framebuffer uploads are keyed by the runtime frame sequence and session epoch, rather than the more frequent bridge heartbeat.

On macOS 14 and later, presentation uses `CAMetalDisplayLink` on the main run loop in common modes, with minimum/maximum/preferred frame rate all set to 60 and preferred frame latency set to one. Its callback supplies the drawable directly to the renderer; the MTKView timer is paused and this path never asks `currentDrawable`/`nextDrawable`. Drawable dimensions follow window/backing-size changes. macOS 12/13 retain the MTKView 60 Hz timer path. Neither scheduler changes game simulation, frame acquisition or asset polling rates. A requested rate is not a measured result.

The view and its actual `CAMetalLayer` explicitly synchronize drawable pixel dimensions from `convertRectToBacking(view.bounds)` during layout, backing/display changes and fullscreen entry/exit. Automatic MTKView drawable resizing is disabled because its reported size can update before the display-link layer. Already-supplied drawables with old dimensions are skipped until the next display-link callback; no second drawable is fetched. Fullscreen uses the display area while fitting the 16:9 game image inside it. The hidden startup status label bounds only its own width (`<=85%` of the view and `<=560` points); it does not constrain the game window. The regression activates this game-only overlay branch, hides the label, and checks that fullscreen content occupies the owning screen width.

Widescreen extends the horizontal field of view. The vertical framing and central 4:3 image retain their scale; additional scene appears at both edges. Menus and automatic original-framebuffer fallback retain the original source aspect. `Tests/check_geometry.py` checks this against the actual projection code without launching a game.

Metrics retain the original presentation/callback/drawable-wait series and identify the active display scheduler. `foreground_presented_fps` and its interval percentile use only consecutive unique presentations from the same active-window segment, excluding focus/minimization gaps. `display_target_hz` measures unique target presentation timestamps received from the Metal display link. The offscreen path is explicitly labelled unpaced and does not measure displayed FPS.

Per-race assets are published only when complete. The client checks `assets.epoch`, `world_scene` and `cars_scene`, prepares replacement Metal resources off the UI thread, and adopts them together on the main thread. While assets are missing, mismatched or loading, the original framebuffer remains visible. This supports tracks beyond the initially bundled scene when the bridge extracts their actual assets.

Original menus, loading screens, pause screens and HUD come from the runtime framebuffer. Supported descriptors are `{path,width,height,stride,format}` with `bgra8`, `rgba8`, `rgb565`, or `png`; raw frames are copied into a new texture for each accepted state. Frame files must be complete before state publication. Full-frame fallback preserves aspect ratio. No menu or HUD imagery is generated.

For native race rendering, `hud.complete` requires validated original overlay pixels. Rally publishes `hud.layers` as transparent premultiplied BGRA textures with `{path,format:"bgra8",x,y,width,height,stride,anchor}`. Alpha comes from original accepted Voodoo framebuffer writes, including guarded original RPM-needle drawing; underlying 3D colors are not classified by color. Edge regions anchor left/right, the progress strip centers, and the final source row stretches. Files are complete before the state adopts their sequence. `hud.rects` remains available for the original rear-view mirror. Missing exact coverage falls back to the complete original picture.

Bundled Upgraded games render at the window’s pixel resolution, including Retina scaling, with a 16:9 view and full-track draw distance. The initial desktop window fits its own screen and keeps a 16:9 content aspect. If the display supplies another drawable shape, the selected view is fit inside it. Menus and automatic full-frame fallback preserve their original source aspect; the title says “Original view” during fallback. Bundled games expose no separate resolution/aspect/distance menu. Standalone previews and explicit --live diagnostics retain their developer controls and CLI resolution options.

Rally's original BCK panorama is exported from the owned MAP archive and mapped using the original camera-heading/pitch formula. Original sky flags and ground colors are read with each atomic pose. Clockwise face culling matches original polygon normals. `hidden_instance_ids` honors the exact followed-car scene index in bumper camera modes 2/5; chase views retain the car.

Only real Cocoa key events enter the input feed. Arrow keys, letters, digits, Enter, Escape, Space, Tab, Backspace, modifiers and F1–F12 map to canonical DOS key names. Preview camera shortcuts and mouse-wheel orbit are disabled in live mode. The client atomically publishes the complete held-key set and monotonic tap counters on transitions plus a 10 Hz lease heartbeat. Focus loss, deactivation and closing publish an empty, unfocused state; the bridge must release its owned keys and enforce the lease timeout independently. No OS or game key-event automation is part of the renderer.

Screamer 1 uses live independent actor-part transforms and original A0 reflection mapping; its Q14 pose quantization and other palette effects remain approximate or omitted. Rally/Screamer 2 wheel/part poses remain captured and their reflection UVs remain approximate. Transparent polygons are sorted by material batch. Runtime metrics count native-world and original-fallback frames separately and distinguish native race rendering from the original framebuffer fallback and report live-state age, interpolation delay, accepted-state count and parse failures. A 60 Hz presentation count does not imply that original framebuffer content itself has 60 unique game frames.

Validation: the isolated China Arcade test exercised normal guest menu input, acceleration, steering, pause/resume, and key release. A simultaneous live native race measured 59.583 displayed FPS; original clock increments indicated 32.997 physics steps/s over a short observation. A separate 3840×2160 live offscreen render passed. See `../Validation/LIVE.md` for measurements and scope. Time Attack and other non-six-car modes currently retain the original framebuffer fallback; six-car native races, other tracks and long sessions need wider validation. The original sky and exact transparent HUD are now composed separately; the mirror retains its original source pixels. This remains an experimental playable renderer.
